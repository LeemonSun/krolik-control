# Повторный аудит Krolik Control 0.6.1

18 октября 2026 · Автор проекта: LeemonSun

## Исправления по сообщениям пользователя

1. Выбранный выход проверки динамиков не сохранялся в модели. Добавлены явные значения для динамика и микрофона, сохранение в состоянии страницы и восстановление после переходов/перезагрузки окна.
2. Раздел диагностики сначала строился как пустая категория, затем второй раз как собственная страница. Между этими действиями браузер ограничивал прокрутку по высоте пустого содержимого. Теперь раздел зарегистрирован в общем диспетчере и строится один раз.
3. При изменении состояния весь HTML заменялся. Теперь совпадающие элементы обновляются на месте с устойчивыми ключами. Сохраняются фокус, положение ввода, выделение неизменившегося текста, раскрытые подробности и позиция прокрутки. Проверено и перетаскивание мышью с зажатой кнопкой при обновлении результата.
4. Убраны рекламные заголовки и общие лозунги на старте и в разделах. На обзоре — название компьютера, Windows, оборудование и переходы к действиям. Сведения об ошибках/измерениях остаются под раскрытием; подтверждения изменения системы и записи микрофона сохранены.

## Дополнительные найденные проблемы

5. Первый запрос состояния мог завершиться раньше загрузки последнего UI-модуля. История навигации создавалась с неполным списком разрешённых страниц и могла вернуть обзор вместо последнего раздела. Запуск перенесён после DOMContentLoaded; регрессия воспроизводится искусственной задержкой последнего модуля.
6. Быстрые повторные нажатия могли пересекаться до получения состояния задания. В интерфейсе добавлена немедленная блокировка действия; на сервере звуковой сигнал, индикатор микрофона и прослушивание записи взаимоисключаются.
7. Страница проверки не показывала ошибку тестового сигнала; уведомление об отправке появлялось до окончания. Теперь отображаются фактические состояния «Воспроизведение», завершение и понятная ошибка с подробностями отдельно. Демонстрация прямо сообщает, что реальный звук не воспроизводился.
8. Исчезнувший выбранный выход мог незаметно замениться первым доступным. Выбор сохраняется, появляется пометка «недоступно», запуск для него блокируется до повторного подключения/выбора другого устройства. При входе в раздел запрашивается свежий список устройств.
9. Последняя вкладка и выбранный результат не сохранялись. Они включены в проверяемое состояние страницы; сохранение результата проверено после перезагрузки окна.
10. Удаление записи во время захвата могло выглядеть успешным, а завершившийся захват снова заполнял память. Удаление заблокировано до окончания записи/воспроизведения.
11. Под ошибкой звукового теста общий компонент выводил кнопку повторения без поддерживаемого маршрута. Она убрана; повтор выполняется кнопкой соответствующего устройства.
12. Для запросов API добавлена проверка объекта вместо списка/строки/null; длительность наблюдения принимается только целым значением 30 или 60 секунд.

## Проверки и границы

- 215 Python-тестов прошли, включая восемь новых проверок блокировок, удаления записи, валидации и сохранения выбора.
- Основной браузерный прогон: 22 страницы; ключевые экраны при 3 размерах × 4 масштабах; ошибок JavaScript и горизонтальных переполнений не найдено.
- Отдельно прошли сценарии диагностики, программ на подменённой чистой Windows, жизненного цикла приложения и новый сценарий сохранения состояния/отключения устройств/выделения/прокрутки.
- Windows x64 сборка создана. Файлы в пакете сравниваются с исходниками, проверяются SHA-256, PE-ресурсы, вложенный payload Setup и целостность ZIP.

Автоматические проверки интерфейса выполнялись в Linux/Chromium с демонстрацией и тестовыми подменами, не на пользовательском оборудовании. Здесь не запускались Windows EXE, настоящий Setup, Core Audio, UAC и системные изменения. Проверки реальных звуковых устройств, масштабирования Windows и установки/обновления/удаления перечислены в WINDOWS-TEST.md. Исполняемые файлы пока без доверенной цифровой подписи; исправления интерфейса не устраняют предупреждение SmartScreen.
