# Актуальный статус 0.10.0

Эта матрица ещё не выполнена на Windows. Текущие автоматические результаты — TESTED.md; 61 сценарий разбирался PowerShell 7, аппаратные вызовы подменялись. Отдельно проверить новый микшер, NVML/ADL, NVMe, переименование/возврат, задачи планировщика и независимый процесс возврата экрана при аварийном завершении.

# Проверка новых функций 0.9.0

Сначала на отдельной тестовой Windows распаковать portable. Проверка чтения без изменений:

```powershell
powershell.exe -NoProfile -File .\Check-Windows.ps1 -Bundle .
```

Сценарий сохраняет JSON в «Документы». Он не проверяет установку/применение. Подробная матрица из 100 сценариев: ACCEPTANCE-1.0.md.

Новые обязательные проверки: RAM 128–1024 МиБ и отмена/недостаток памяти; выбранный процесс игры, кадры и прекращение ETW после отмены; отдельные GPU и VRAM; Temp с блокировкой/junction/подменой; экспорт драйверов и отказ копии; HDR/clone/extend/встроенный/внешний с отменой и отключением; 3 роли Core Audio и возврат; часовой пояс и возврат; WinGet на чистой Windows, старые версии после неудачного обновления. Нужны Windows 11 и 10 x64; HDR может быть недоступен на старом интерфейсе.

Эти испытания не выполнены в Linux. Не запускать опасные испытания отказа питания/BIOS на основном ПК. Проверка разгона — только на заявленной совместимой модели с известным способом восстановления и доступом владельца к ключу BitLocker.

# Проверка на настоящей Windows

Демонстрация доступна из исходников через Demo.cmd или параметр --demo. Для рабочего запуска откройте KrolikControl.exe из полностью распакованной portable-папки. Установленный Python не требуется. Первую проверку изменения системы удобно проводить в виртуальной машине; реальные режимы мониторов проверяются на физическом ПК.

1. **Запуск и сканирование.** Окно появляется, категории доступны. Сравнить GPU, RAM, мониторы и сеть с Windows. Замерить время первого появления режимов и отдельно завершения метаданных. Монитор должен работать до завершения фонового определения питания/сети. Ошибка сканирования не должна показывать демонстрационные данные.
2. **Без выбранных изменений.** Пройти категории, не выбирать параметры. Кнопка применения не должна запускать изменения.
3. **Одна обратимая настройка.** Выбрать «Показывать расширения», применить. Проверить Проводник. Нажать откат и сравнить с исходным состоянием.
4. **Звук.** Выбрать безопасную громкость конкретных динамиков, применить и сравнить со штатным микшером. Проверить mute микрофона, затем откат. Не выбирать слишком большую громкость для первого теста.
5. **Монитор.** Сравнить список разрешений и частот со свойствами дисплея. Выбрать уже поддерживаемую частоту. Не подтверждать: через 20 секунд должен вернуться исходный режим. Повторить и подтвердить, проверить сохранение. Отдельно проверить второй монитор и поворот.
6. **Питание.** Выбрать существующую схему и таймер, проверить в Windows. Откатить. На ноутбуке отдельно проверить питание от батареи.
7. **Языки.** Сохранить текущий набор. Выбрать RU/EN, применить; проверить Win+Space. Проверить порядок после нового входа, затем откатить.
8. **Браузер.** Нажать «Установить сейчас», затем отменить подтверждение: установки быть не должно. Повторить и подтвердить, проверить результат. Остальные выбранные настройки должны остаться в очереди. При отсутствии WinGet подтверждённая очередь автоматически подготавливает официальный компонент Microsoft; Store вручную открывать не нужно.
9. **Драйверы.** Сравнить устройства с диспетчером устройств, версии и коды проблем. Проверить порядок GPU/CPU/чипсет/сеть и объединение CPU-записей. Выбрать одно устройство, нажать «Обновить», сверить предложенный пакет. Отменить: установки быть не должно. После отдельного подтверждения проверить версию, журнал и необходимость перезагрузки.
10. **Администратор.** Проверить, что обычный режим сообщает о необходимости прав для DNS и обновлений. Нажать «Перезапустить с правами» под тем же пользователем. Для DNS записать прежнее состояние, изменить только выбранный адаптер, проверить и откатить.
11. **Ошибки.** Отключить интернет перед поиском/установкой: ошибка должна быть видна, без ложной отметки «Установлено». При отмене очереди текущая установка завершается, следующие пункты пропускаются.
12. **Профили и журналы.** Сохранить профиль и загрузить обратно. Неподдерживаемый режим/чужой адаптер должны отклоняться. Проверить JSONL-журнал, перезагрузить окно и повторить сканирование.

Если что-то не работает: в «Истории» нажать «Экспорт диагностики», сохранить JSON. Указать сборку Windows, какое действие выбрано и что получилось. Полный ключ Windows не нужен.

13. **Настоящий EXE.** Запустить на Windows x64 без установленного Python, из папки с пробелами и русскими буквами. Убедиться, что рядом сохранена папка data. Проверить появление окна и сообщения об ошибке при намеренно отсутствующей data в отдельной копии.
14. **Права.** Отменить запрос UAC: исходное окно остаётся рабочим. Подтвердить под тем же пользователем: выбор восстанавливается. Другой аккаунт администратора должен отклоняться до применения.
15. **Перезапуск и откат.** Изменить одну обратимую настройку, закрыть приложение, запустить заново. Проверить историю и доступный откат, вернуть значение.
16. **Каталог и профили.** Проверить отсутствие переходов в окна настроек Windows, причины ограничений, избранное и личные профили, поиск в неправильной раскладке. Проверить применение только раздела: остальные выбранные пункты остаются в очереди.

17. **Новые параметры ввода.** Проверить основную кнопку, двойной щелчок, Ctrl-поиск указателя, скрытие при печати и горизонтальную прокрутку при поддержке мышью. После закрытия программы значения должны сохраняться. Проверить точный откат, включая исходный двойной щелчок, которого нет в списке вариантов.
18. **Повторное обнаружение.** Подключить/отключить второй монитор или USB-аудиоустройство, повторно открыть категорию. Недоступный режим нельзя применить; остальные выбранные настройки не теряются.

## 0.5: чистая Windows и программы

1. Открыть программы без WinGet: карточки доступны, Store и PowerShell вручную не нужны. Вход в раздел ничего не устанавливает.
2. Выбрать Opera/Chrome, отменить подтверждение: ни компонент, ни приложение не устанавливаются.
3. Подтвердить установку: подготовка компонента Microsoft, затем выбранный пакет; PATH/перезапуск приложения не нужны.
4. На время загрузки отключить сеть: понятная ошибка, приложение пропущено, временные файлы удалены. Включить сеть, повторить подготовку и установку.
5. Отменить загрузку подготовки; очередь не продолжает ставить приложения. Уже запущенный сторонний установщик при обычной остановке не обрывается.
6. На ПК с рабочим WinGet подготовка не скачивает его заново. Уже установленный пакет не переустанавливается.
7. Проверить x64-зависимости App Installer, подпись Windows и поведение при отключённом Appx deployment. Не включать обход политик.
8. Проверить установленную программу в UI и Windows; поиск обновлений выбранного пакета; ложного сообщения «всё обновлено» при ошибке нет.

## 0.6: диагностика, бенчмарк и Setup

- Setup: чистая Windows без Python; установка от обычного пользователя; ярлык «Пуск» и необязательный Desktop; версия/удаление в списке приложений. Обновление при закрытом приложении, отказ при открытом, восстановление прежней папки при неудаче. Удаление сохраняет пользовательские отчёты/настройки/копии.
- Звук: mute/нулевая громкость устройства, отдельно заглушенная сессия, остановленные службы, отключённое/исчезнувшее устройство, запрет микрофона текущего пользователя и политикой. Исправление с подтверждением, readback, откат текущего исправления и отказ откатывать через старый отчёт.
- Голос: выбранный микрофон, 5 секунд речи + секунда паузы, прослушивание, перегруз/тишина/фон, удаление из памяти, новая запись и перезапуск. Старый отчёт не должен воспроизводить новую запись. Левый/правый канал и моно-выход.
- Сеть: кабель отключён, APIPA с DHCP, статический IP без DHCP, неверный DNS, недоступный внешний узел, VPN/прокси. Подтверждённый renew не трогает статическую конфигурацию. DNS-кэш очищается только после воспроизведения ошибки.
- Скорость: доступный/заблокированный Cloudflare, TLS, неполный ответ, медленное соединение, отмена, короткая передача без достаточных отсчётов loaded latency. Сопоставить с независимым измерением того же узла/маршрута; не объявлять провайдера виноватым по одному серверу.
- Наблюдение: 30/60 секунд с реальной игрой; сравнить CPU/ядра/GPU/память/диск с Windows-счётчиками. Недоступные GPU-счётчики, несколько процессов одного движка, несколько GPU, фоновая запись, отсутствие дисковых операций.
- Бенчмарк: CPU single/multi до 64 потоков, нехватка памяти/места, HDD/SSD, D3D11/iGPU/dGPU, отсутствующий shader compiler, disjoint timestamp, readback шейдера, отмена и двухминутный предел. Временный файл должен удаляться; имени GPU и накопителя доверять только после проверки на этом ПК.
- Драйверы: экспорт, копирование на USB, возврат папки после переустановки, выбор копии, несовместимые/неподписанные пакеты и перезагрузка. Не форсировать драйвер ниже ранжированного Windows.
- Компоненты Windows: Healthy/Repairable/NonRepairable, offline RestoreHealth, отмена закрытия во время восстановления и сохранённый результат без автоматической перезагрузки.

## Регрессии 0.6.1 на реальном оборудовании

1. Подключить два аудиовыхода. Выбрать второй в «Проверка и исправление → Звук и голос». Прослушать левый и правый каналы: выбор должен остаться вторым после окончания и после ошибки. Закрыть и открыть приложение, сравнить выбор.
2. Во время проверки нажать кнопку несколько раз и перейти в «Звук». Второй звуковой тест не должен накладываться на первый. После окончания кнопки снова доступны.
3. Отключить выбранное USB-устройство и обновить список. Оно помечается недоступным; сигнал не перенаправляется в другое устройство. Подключить снова и повторить.
4. Получить длинный результат, прокрутить вниз, выделить текст мышью и оставить кнопку зажатой при фоновом обновлении. Страница и выделение не должны сбрасываться. Повторить с открытыми сведениями и масштабами 100/150%.
5. Выбрать старый результат, другую вкладку проверки, закрыть и открыть окно: вкладка и результат должны сохраниться.
6. Запустить запись/прослушивание. Удаление записи недоступно до окончания; после удаления старый отчёт не должен воспроизводить новую запись.

## Регрессии 0.6.2

1. Во время применения открыть другой раздел. После успешной/ошибочной операции поля должны разблокироваться; недоступные параметры остаются недоступными. Сразу после завершения нажать «Повторить»: дождаться повторного чтения и проверить точный список.
2. Подготовить подтверждение, быстро нажать другой пункт или перейти в другой раздел: состав не подменяется, старое окно не открывается позднее.
3. Отложить громкость 20%, затем немедленно установить 70% через исправление. После завершения и перезапуска в очереди должны оставаться 20%. Аналогично проверить другие значения монитора/яркости.
4. Отменить исправление микрофона/аудиосессии: сравнить реальное значение, кнопку отката и сохранённый результат после перезапуска.
5. На копии тестовых данных испортить один report-*.json: приложение запускается, другие результаты доступны. Сетевое исправление не выбирается автоматически во вкладке звука.
6. Проверить первую установку, обновление, удаление и повторный запуск Setup одновременно. В тестовой VM смоделировать отказ записи ярлыка/регистрации: прежняя версия и ярлыки должны восстановиться.

## 0.7.0: Мой ПК

1. Открыть «Мой ПК»: появляются реальные модели, экраны и основной выход/микрофон. Наушники, колонки и HDMI различаются; неизвестный тип не выдаётся за колонки. Отключить экран/USB-аудио и нажать «Обновить устройства».
2. Проверить CPU/RAM/GPU по Диспетчеру задач. На нескольких GPU нагрузка должна оставаться общесистемной. Неподдерживаемые счётчики показывают тире.
3. Проверить температуры без провайдера и с включённым WMI Libre Hardware Monitor/Open Hardware Monitor. Данные диска/ACPI не должны попадать в CPU.
4. Уйти с вкладки: через 8–10 секунд сборщик PowerShell завершается; вернуться — возобновляется один сборщик. Скрытие окна прекращает запросы. Запустить бенчмарк: мониторинг приостанавливается. Закрыть приложение: его процесс мониторинга не остаётся.
5. Сверить место на томах, типы накопителей, отсутствие выдуманного здоровья/температур для USB/RAID.
6. Запустить события и сон без/с правами администратора. При отсутствии прав нет ложного вывода об исправности. Windows не меняется.
7. Профиль с Chrome на чистой Windows без WinGet оставляет Chrome в очереди; отмена подтверждения ничего не устанавливает.
8. Имитировать отказ сканирования устройств: видны ошибка и повтор; прежний список сохраняется.

## 0.8.0: BIOS и память — обязательные испытания на оборудовании

- Windows 11 и Windows 10 x64: чтение без администратора/с администратором; UEFI и Legacy; отказ CIM не блокирует окно.
- По одному реальному поддерживаемому Lenovo, Dell и HP: проверить имена, перечисления и коды методов. Сначала чтение, затем обратимая неразгонная настройка с владельцем машины; проверить после перезапуска и вернуть прежнее значение.
- XMP/EXPO: только на модели, которая явно экспортирует профиль через интерфейс OEM. Не считать наличие BIOS AMI признаком совместимости.
- Пароль/сертификат/политика BIOS, неизвестное состояние пароля и read-only/physical-presence: запись заблокирована; пароль не запрашивается.
- Проверить защищённый BitLocker диск: подтверждение доступности ключа без чтения ключа и без отключения защиты. Нужны также проверки отказа cmdlet и возврата неизвестного статуса.
- Перезагрузка не содержит /f и использует /t 0. Несохранённый редактор может остановить запрос; интерфейс не утверждает, что перезагрузка уже состоялась.
- Таймаут во время записи, потеря питания/закрытие окна, заполненный диск: намерение сохранено до вызова; повторная запись не производится сама. Проверить результат после следующей загрузки.
- После смены платы, модулей, версии прошивки или настройки между просмотром и записью действие отклоняется.
- Убедиться, что принятие OEM не считается фактически применённым до смены идентификатора загрузки.

Эти испытания ещё не выполнены в данной среде. Проверки с CIM-двойниками не подтверждают совместимость физической платы.
