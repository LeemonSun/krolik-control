# Krolik Control 0.8.0 — BIOS и память

19 октября 2026 · Автор проекта: LeemonSun

## Результат

Добавлена отдельная вкладка «BIOS и память». Вкладка «Мой ПК» из 0.7.0 сохранена; карточка платы ведёт в новый раздел. Это сборка с реализованным OEM-мостом и автоматическими проверками, а не подтверждение совместимости со всеми платами.

### Управление из приложения

Сценарий: определить возможности → выбрать возвращённое прошивкой значение → отдельное подтверждение → сохранить намерение и прежнее значение → вызвать метод OEM → предложить перезагрузку → перечитать параметр после новой загрузки Windows.

- Lenovo: Lenovo_BiosSetting, Lenovo_GetBiosSelections, Lenovo_SetBiosSetting, Lenovo_SaveBiosSettings, проверка Lenovo_BiosPasswordSettings.
- Dell: EnumerationAttribute и BIOSAttributeInterface.SetAttribute из root/dcim/sysman/biosattributes, проверка PasswordObject из root/dcim/sysman/wmisecurity.
- HP: HP_BIOSEnumeration, HP_BIOSPassword и HP_BIOSSettingInterface.SetBIOSSetting из root/HP/InstrumentedBIOS.
- Адаптер выбирается по производителю компьютера и наличию конкретных классов, а не по одному имени AMI в BIOS.
- Для записи допускается ограниченный список точных имён: XMP/EXPO и профили памяти, обмен Fn/Ctrl, поддерживаемые варианты питания USB и Wake-on-LAN. Неизвестные настройки не становятся управляемыми автоматически.
- Значения поступают из перечисления OEM. Произвольных частот, таймингов, напряжений, команд, адресов и записей в NVRAM нет. Профиль памяти показывается как управляемый только когда он действительно экспортируется и доступен для записи.
- У Lenovo SaveBiosSettings сохраняет также уже подготовленные другими утилитами изменения. Это явно указано в подтверждении; перед действием нужно закрыть прочие утилиты BIOS. Независимой транзакции на одну настройку этот API не гарантирует.

### Что доступно на остальных ПК

UEFI/Legacy через GetFirmwareType; BIOS/плата, модули RAM по слотам, сообщённые SMBIOS скорость и напряжение; статусы Secure Boot, TPM, виртуализации и защиты системного диска. Недоступные сведения остаются неизвестными.

Можно сохранить локальный снимок показаний RAM, затем сравнить их после возвращения в Windows. Снимок привязан к модели платы/системы и составу модулей; это не полный дамп BIOS и не гарантия восстановления. Смена состава модулей или платы не выдаётся за результат изменения частоты. Скорость из SMBIOS не доказывает наличие XMP/EXPO или стабильность разгона; чтения SPD в этой версии нет.

Встроен ориентир по меню памяти ASUS/MSI, основанный на официальных руководствах. Для других плат используется общий путь с указанием свериться с руководством модели. Названия меню могут отличаться между версиями BIOS.

Кнопка перехода в UEFI отправляет подтверждённый запрос Windows. Используется shutdown.exe /r /t 0 /fw; обычная перезагрузка — /r /t 0. Нет /f и таймера больше нуля, который неявно добавлял бы /f. Открытые приложения могут остановить перезагрузку; принятие запроса не объявляется завершённой перезагрузкой. Наличие режима UEFI не гарантирует, что конкретная прошивка примет /fw.

## Защита действий

- Нет автоматических BIOS-записей при запуске, сканировании, переходах, восстановлении очереди или обычном применении параметров Windows.
- Нужны права администратора, завершение других операций, отсутствие неподтверждённого режима монитора, свежая проверка и одноразовое подтверждение со сроком 120 секунд.
- Перед реальной операцией перечитываются модель платы, BIOS, состав памяти, загрузка, OEM-параметры и защита диска. Изменение этих сведений отменяет устаревшее действие.
- Непосредственно в PowerShell повторно проверяются производитель, доступность метода, отсутствие установленного/неизвестного пароля, текущее значение и принадлежность нового значения перечислению. Для HP/Dell учитываются ограничения записи, для HP — требование физического присутствия. Дубли имён не допускаются к записи.
- Пароли BIOS не собираются, не хранятся и не обходятся. Применение при пароле или неизвестном состоянии защиты заблокировано. Политики и сертификаты OEM могут дополнительно отклонить метод.
- При активной или неизвестной защите диска требуется подтверждение доступности ключа восстановления на другом устройстве. Сам ключ не запрашивается и не считывается; защита не отключается и не приостанавливается.
- Для профиля RAM требуется отдельное подтверждение совместимости и знания способа восстановления после неудачной загрузки.
- Атомарный журнал намерения записывается до вызова OEM. При отказе диска вызов не выполняется. При таймауте/неоднозначном результате состояние становится неподтверждённым; автоматического повтора нет.
- Принятый параметр остаётся ожидающим перезагрузки. После нового идентификатора загрузки сравнивается значение: совпало, отличается либо недоступно. Результат другой платы не подтверждает исходную запись.
- Возврат прежнего значения — отдельное подтверждаемое действие и только если прежний вариант снова предоставлен OEM. Автоматическое восстановление незагружающегося ПК не обещается.
- Повреждённый журнал не ломает страницу и блокирует новые действия. Закрытие штатного окна ожидает завершения BIOS-задачи. Принудительное завершение процесса/потерю питания нельзя считать безопасным завершением записи.
- Результаты и снимок не содержат серийных номеров модулей, BIOS-паролей или ключей восстановления.

## Исправлено в ходе прогонов

1. Выбранный вариант BIOS терялся после отмены подтверждения. Теперь хранится в состоянии страницы.
2. Повторное BIOS-действие могло не обновить сведения. Для отслеживания используется отдельная отметка завершения, обновление не теряется при параллельном чтении.
3. Общий механизм кэширования мог вернуть старые данные после повторной быстрой задачи с теми же метаданными. Теперь завершение и ошибка задачи изменяют ревизию данных. Добавлена регрессионная проверка.
4. Ошибка записи BIOS больше не предлагает бесполезную/опасную кнопку повтора записи: доступно только обновление и проверка результата.
5. Замена уже сохранённого снимка требует подтверждения. При закрытии BIOS-операция не считается законченной раньше ответа OEM.
6. Отсутствующее поле PasswordState не трактуется как отсутствие пароля; неизвестный доступ закрыт.

## Проверки

- Два полных модульных прогона по 267 тестов: проходят.
- Новый браузерный сценарий BIOS: два завершённых прогона после исправлений. Проверены OEM-перечисления на тестовом сервере, снимок, подтверждение его замены, обязательные отметки защиты/памяти, отмена, ожидание перезагрузки, проверка после смены загрузки, возврат прежнего значения, восстановление страницы, недоступная/защищённая прошивка и обработка ошибки без повторной записи.
- Размеры 600/800/1024/1240/1440 px и масштаб 100/125/150%: горизонтального переполнения нет; проверены светлая и тёмная темы.
- Общий браузерный сценарий приложения, «Мой ПК», care-ui, apps-ui, audit-ui, reliability-ui и lifecycle: проходят.
- PowerShell 7.6.7: синтаксис трёх новых сценариев; два прогона 15 изолированных OEM-сценариев. Для каждого Lenovo/Dell/HP: успех, защита, изменение текущего значения, недопустимый вариант и отказ метода. Используются подставные CIM-объекты; методы физических устройств не вызываются.
- Четыре проверки транзакций установщика с подставными реестром/ярлыками: проходят. Это не испытание реестра/COM в Windows.
- Windows x64-сборка: закреплённый Python 3.14.8, PE x64, хеши и соответствие исходникам, целостность ZIP и наличие актуального payload в Setup.

## Непроверенные условия

В данной среде нет завершённых испытаний на настоящих Windows 11/10 и физических платах. Не проверены совместимость OEM-классов на конкретных моделях, Windows PowerShell 5.1, коды реальных прошивок, вход в UEFI, BitLocker и практическая настройка RAM. Эти пункты перечислены в WINDOWS-TEST.md. До этих испытаний нельзя объявлять BIOS-мост универсальным или промышленно проверенным. Будущие Windows обслуживаются через проверку возможностей, но совместимость с несуществующими/неиспытанными версиями не гарантируется.

На потребительских ASUS/MSI/Gigabyte/ASRock универсальная запись EXPO/XMP этой версией не реализована. Само наличие AMI BIOS, процессора AMD/Intel или работающего Ryzen Master не создаёт документированный общий интерфейс для нашей программы. Неподходящий SCEWIN/чужие драйверы и смещения NVRAM не включены. Число «95% покрытых настроек» не измерялось и не заявляется.

## Следующие полезные функции

1. Настоящая проверка стабильности RAM с контролем записанных данных, ограничением объёма и отменой. Текущий тест пропускной способности этого не заменяет.
2. Отчёт игровой сессии с временной шкалой нагрузки, доступных температур и просадок; отдельно измерять FPS/frametime, а не выводить их из процента GPU.
3. Автоматическая копия выбранных драйверов перед обновлением и понятный путь восстановления, расширяющий существующее ручное сохранение драйверов.
4. Проверенные адаптеры конкретных плат/BIOS с паспортом совместимости; только после реальных испытаний расширять прямую настройку памяти.

Полный общий аудит лишних функций и измеримое покрытие пользовательских задач — следующий отдельный этап, как договорено с автором.
