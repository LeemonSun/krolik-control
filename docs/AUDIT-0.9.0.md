# Аудит Krolik Control 0.9.0

Автор проекта: LeemonSun. Дата: 19 октября 2026. Предыдущая сборка: 0.8.0.

## Что изменилось

Добавлены отдельная очистка пользовательского Temp, проверка данных RAM собственным модулем, запись кадров выбранного приложения через PresentMon 2.6.0, автоматическая копия сторонних пакетов перед обновлением драйверов, HDR/схемы экранов, роли основного аудиоустройства и возврат. В «Мой ПК» появились отдельные GPU с данными DXGI; в Windows — часовой пояс, буфер обмена, уведомления и Print Screen. Готовые профили включают программы. Размер PresentMon менее 1 МиБ; тяжёлый новый движок или сенсорный драйвер не добавлялись.

## Исправленные крайние случаи

- Изменение параметров RAM переживает перерисовку и передаётся в задание; в демо учитываются выбранные значения.
- Ни незавершённый тест RAM, ни нехватка памяти, ни ошибка паттерна не становятся «успешной проверкой». Отдельно проверена настоящая инъекция повреждённых данных в тот же C-движок на Linux; в выпускаемом EXE этой тестовой опции нет.
- В очистку не попадают ссылки/junction, свежие файлы, документы, загрузки и корзина. Список одноразовый, истекает через 2 минуты; изменившиеся/занятые файлы пропускаются. В Windows удаление реализовано через проверенный открытый файловый дескриптор, но ещё требует аппаратной проверки.
- Состав автоматической копии драйверов проверяется целиком: дополнительные, пропавшие, изменившиеся файлы и ссылки останавливают восстановление. Частичная копия не публикуется. Отказ копии блокирует следующую пакетную установку обновлений.
- После HDR/схемы перечитываются устройства. Неподтверждённая картинка возвращается таймером, пока приложение работает. Это не независимая системная служба возврата при аварийном завершении процесса.
- Выбор роли/устройства звука сохраняется при перерисовке. Возврат блокируется, если устройство отключилось или текущий выбор уже изменён; повторный возврат отклоняется.
- FPS считается только для выбранного PID и одной цепочки с максимальным числом кадров. Проверяется время запуска процесса, игнорируются NaN/неверные интервалы; отсутствие кадров даёт ошибку, не нулевой FPS. CSV удаляется после анализа.
- При отмене/превышении времени останавливаются собственный процесс PresentMon и только его уникальная ETW-сессия. Создание сборщика датчиков перенесено до запуска процесса.
- Установка/обновление проверяет отмену и место на системном диске. Для обновления недостаточно существования программы: требуется ожидаемая версия, либо честный статус «не подтверждено»/«после перезагрузки».
- Часовой пояс выбирается из списка Windows и сохраняет старое значение для возврата. PowerShell в Windows вызывается по системному абсолютному пути.

## Границы реализации

Настоящая Windows в данной среде не запускалась. Все аппаратные действия — включая новые HDR, Core Audio, ETW, DXGI и удаление через Win32 — нуждаются в проверке на Windows 11/10. Переключение основного звука использует недокументированный PolicyConfig и явно помечено экспериментальным. Современный интерфейс HDR может отсутствовать на старой Windows; тогда действие недоступно.

Заявлены только измеренные интервалы отправки кадров. Это не частота фактического показа, не задержка монитора и не доказательство причины просадок. Проверка RAM охватывает выделенную область процесса. Температуры требуют уже работающего WMI-провайдера LHM/OHM; отсутствие источника явно отображается. Нагрузка GPU — 3D-движок, не все возможные аппаратные блоки. DXGI сообщает выделенную ёмкость, не текущее использование VRAM.

Универсальная настройка BIOS любого производителя, ручные напряжения, прямое программирование NVRAM, полная копия BIOS, DPI/ICC/DDC и выбираемые дробные частоты не реализованы. Фирменные драйверы вне Microsoft Update не загружаются универсальным подборщиком. Перечень Windows-ссылок в исходном каталоге не считается нативной реализацией соответствующих функций; основной каталог показывает действующие элементы приложения.

Программы устанавливаются через автоматически подготавливаемый официальный WinGet. Пользователю не нужно отдельно устанавливать его вручную, но зависимость остаётся. Автоматический откат драйвера к предыдущему пакету не обещается: копия — отдельный инструмент восстановления, а не гарантия успешной загрузки Windows.

## Проверки и выпуск

Точные результаты и команды: TESTED.md. Дополнительная Windows-приёмка: WINDOWS-TEST.md и ACCEPTANCE-1.0.md. Полное состояние 20 направлений: ROADMAP.md.

Сборка воспроизводится build_portable.py с закреплённым SHA-256 Python и PresentMon. Возможность SignTool требует настоящего сертификата и Windows. В этом выпуске собственные EXE не подписаны; исключения в защите Windows не добавляются. Сертификат не создаёт мгновенную репутацию SmartScreen. Автообновления Krolik Control пока нет: не задан канал и ключ подписи выпусков.

Новая версия остаётся проверяемой сборкой 0.9.0. Называть её законченным стабильным продуктом 1.0 до Windows-приёмки было бы неверно.
